#### 🟡 中危 P1 — 问题 1 — 数量单元格未做空值保护，toLocaleString 可能抛错中断表格渲染

**位置：** `frontend/src/views/warehouse/MaterialOutboundView.vue` 文件，约第 71 行

**问题描述：** 表格列模板直接调用 row.quantity.toLocaleString()。当后端返回 quantity 为 null/undefined（或该字段缺失、为字符串）时会抛出 TypeError，导致整个表格渲染失败，页面白屏。

**当前代码**

```
// ❌ 当前代码
{{ row.quantity.toLocaleString() }}
```

**修改建议：** 改为 Number(row.quantity ?? 0).toLocaleString()，或在数据映射层统一把 quantity 归一化为 number 并给出默认值 0。

**正确做法**

```
// ✅ 正确做法
{{ Number(row.quantity ?? 0).toLocaleString() }}
```

#### 🟡 中危 P1 — 问题 2 — onStockContextChange 异步无竞态保护，过期响应会覆盖最新库存结余

**位置：** `frontend/src/views/warehouse/MaterialOutboundView.vue` 文件，约第 488 行

**问题描述：** 切换物料/仓库会连续发起库存查询，代码未做请求序号或 AbortController 取消。若用户快速切换，先发的请求后返回，会用旧上下文的 stockBalance 覆盖新上下文，导致 overStock 校验基于错误库存放行超量出库（前端仅是提示，服务端仍需强校验）。

**当前代码**

```
// ❌ 当前代码
stockLoading.value = true
try {
  const data = await fetchMaterialOutboundStockBalance({
    materialId: createForm.materialId,
    warehouseId: createForm.warehouseId,
    locationId: createForm.locationId || undefined,
  })
  stockBalance.available = data.available_quantity
} finally {
  stockLoading.value = false
}
```

**修改建议：** 为每次请求分配递增 seq，回调中比对 seq 与当前值再赋值；同时在 finally 中仅当 seq 匹配时才把 stockLoading 置 false，避免并发时 loading 提前结束。修复后验证：快速连续切换物料，DevTools 限速网络，确认最终展示的结余与最后选择的物料一致。
